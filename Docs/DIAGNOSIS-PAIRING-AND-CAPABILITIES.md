# Диагностика сопряжения и анализ возможностей iOS-гаджета для Muse

## 1. Диагностика проблемы: Почему аккаунт не принимает и не фиксирует подключенный гаджет

### 1.1. Суть проблемы
После успешного прохождения шагов на экране сопряжения (обмен ключами BLE, передача Wi-Fi и учётных данных устройства, статус `auth_ok`) гаджет не появляется в аккаунте Muse как активное устройство.

### 1.2. Архитектурная причина
Протокол Muse Gadget разделен на **два независимых этапа**:

```
[Этап 1: BLE Setup / Pairing]  ───▶  [Этап 2: Wi-Fi Runtime / Registration]
CoreBluetooth (BLE)                   WebSockets + Noise XX + Link RPC
(Локальный обмен ключами)             (Регистрация в облаке Muse)
       ▼                                     ▼
 РЕАЛИЗОВАНО В ПРОЕКТЕ                 НЕ РЕАЛИЗОВАНО (СКАФФОЛД)
```

1. **Этап 1 (BLE Pairing)**:
   - Мобильное приложение Muse на основном смартфоне ищет периферийное устройство `MuseGadgetXXXXXX` по BLE.
   - Происходит рукопожатие Community Pairing v5 (P-256 ECDH, HKDF-SHA256, AES-256-GCM).
   - Приложение Muse передаёт гаджету учётные данные устройства (`access_token`, `refresh_token`, `api_url_v2`, `noise_host`, `username`).
   - Гаджет сохраняет их и отправляет зашифрованный статус `auth_ok`.
   - **На этом работа BLE полностью прекращается**: периферийный сервер вызывает `peripheral.stop()`.

2. **Этап 2 (Регистрация на серверах Muse через Wi-Fi/Internet)**:
   - В эталонном SDK (`Vendor/muse-gadget-sdk/linux/src/musegadget/service.py` и `esp32/main/app.c`) после получения токенов гаджет **самостоятельно выходит в интернет**:
     1. Выполняет HTTP-запрос к API:
        ```http
        GET https://api.muse.ai/fetch_vms
        Authorization: Bearer <access_token>
        X-API-Version: 1.0.0
        ```
     2. Сервер возвращает список доступных виртуальных машин (`vm_list`), включая `vm_ws_url` и одноразовый/сессионный `vm_auth_token`.
     3. Гаджет подключается по протоколу WebSocket к адресу:
        ```text
        wss://<noise_host>/v1/noise?vm_id=<vm_id>
        Authorization: Bearer <vm_auth_token>
        ```
     4. Поверх открытого WebSocket гаджет проводит криптографическое рукопожатие **Noise XX** (Curve25519, ChaCha20-Poly1305, SHA-256).
     5. Внутри установленной Noise-сессии открывается управляющий двунаправленный поток:
        ```text
        POST /link-control
        ```
     6. В поток `/link-control` гаджет отправляет JSON-RPC сообщение регистрации устройства:
        ```json
        {
          "type": "req",
          "id": "<uuid>",
          "method": "link.register",
          "params": {
            "node_id": "homelink-xxxxxx",
            "display_name": "iPhone",
            "platform": "ios",
            "version": "0.1.0",
            "device_family": "homehub",
            "model_id": "iphone",
            "is_wakeup_supported": false,
            "commands_v2": { ... }
          }
        }
        ```
     7. Облачная VM проверяет регистрацию и отвечает:
        ```json
        {
          "type": "resp",
          "id": "<uuid>",
          "ok": true
        }
        ```
     8. **Только в этот момент сервер регистрирует гаджет с данным `node_id` за аккаунтом пользователя, и устройство появляется в мобильном приложении Muse.**

### 1.3. Состояние кода в `muse-gadget-ios`
В текущем коде `muse-gadget-ios` (коммит `c5d9e7c`):
- В `App/Sources/Bluetooth/PairingCoordinator.swift` метод `provision()` принимает токены, сохраняет их в Keychain и останавливает BLE:
  ```swift
  try sendJSON(session.encryptStatus("auth_ok")) { [weak self] in
      DispatchQueue.main.asyncAfter(deadline: .now() + 0.5) {
          self?.peripheral?.stop()
          self?.log("BLE stopped; the next stage is Wi-Fi-only Muse VM registration")
      }
  }
  ```
- Сетевой рантайм `App/Sources/Protocol/RuntimeScaffold.swift` содержит лишь набросок `MuseRuntime` и `MuseAPIClient.fetchVMs`, но:
  - он нигде не создаётся и не запускается;
  - криптографический протокол Noise XX для iOS ещё не реализован;
  - протокол Link (`link.register`, `link.invoke`, `link.result`) не реализован.

## 2. Анализ возможностей превращения старых устройств Apple (iPhone / iPad) в Muse Gadget

Старые устройства Apple (начиная с iPhone 6s, SE 1st gen, iPad Air 2, iPad mini 4 на iOS 15+) представляют собой **значительно более мощную аппаратную платформу**, чем типичные микроконтроллеры ESP32 или даже Raspberry Pi 3/4. У них есть встроенный дисплей Retina высокой чёткости, стереодинамики, качественный микрофонный массив с шумоподавлением, качественные камеры, аппаратный нейрочип/GPU, Wi-Fi 802.11ac, Bluetooth 4.2/5.0, аккумулятор (UPS) и защищённый сопроцессор (Secure Enclave).

### 2.1. Сопоставление с эталонным SDK (`facebookincubator/muse-gadget-sdk`)

| Подсистема / Функция | Эталонный SDK (Linux / ESP32) | Возможности на базе старого iPhone / iPad | Статус и план в `muse-gadget-ios` |
|---|---|---|---|
| **Экран и UI** | Текстовый вывод, e-Paper (SenseCAP/Waveshare) или маленькие SPI LCD (240x240 / 320x240) | Полноразмерный цветной Retina-экран (IPS/OLED), поддержка SwiftUI, рендеринг Rich Text, анимаций, карточек, аватара Muse, веб-страниц | **Готово локально**: чат и статусы. Требуется привязать входящие `display.*` к SwiftUI моделям. |
| **Аудио: вывод (TTS / динамик)** | `sounddevice` (ALSA/PulseAudio) в Linux или I2S DAC (MAX98357A) в ESP32 | `AVSpeechSynthesizer` (локальный синтез речи Siri) + стриминг PCM16LE через `AVAudioEngine` / `AVAudioPlayer` | **Частично**: локальный `audio.speak` готов. Требуется сетевой приём аудиопотока из VM Muse. |
| **Аудио: ввод (микрофон / голос)** | USB/I2S микрофон, PCM 16/24 кГц, локальный VAD / `voice_gate.py` | Встроенный микрофонный массив Apple с аппаратным эхоподавлением (AEC) и формированием луча через `AVAudioSession` | **Заглушка**: в `IOSCommandRegistry` есть каркас. Требуется стриминг WAV/PCM или распознавание через `SFSpeechRecognizer`. |

| **Датчики и телеметрия** | Внешние датчики I2C (SHT4x, AHT20, CO2, tVOC) | Акселерометр, гироскоп, магнитометр (`CoreMotion`), барометр (`CMAltimeter`), уровень заряда АКБ, термосостояние (`ProcessInfo.thermalState`) | **Частично**: батарея и аптайм готовы. `CoreMotion` можно подключить одной командой `motion.snapshot`. |
| **Геопозиция** | Отсутствует (или внешние GPS-модули по UART) | Встроенный GPS/ГЛОНАСС (`CoreLocation`), геозоны, точное время | **Заглушка**: готов запрос прав. Реализуется через `CLLocationManager`. |
| **Локальная сеть и умный дом (Skills)** | 40+ навыков в `Vendor/muse-gadget-sdk/skills` (Philips Hue, Shelly, HomePod, Apple TV, Sonos, Smart Plugs) | Сетевой поиск `Network.framework` (`NWBrowser`), Bonjour / mDNS, SSDP, прямое управление локальными IoT-устройствами по HTTP REST | **В планах**: сетевое разрешение добавлено в манифест. iPhone может быть локальным хабом умного дома. |
| **Тактильный отклик** | Вибромотор на GPIO | Taptic Engine (Apple Taptic Engine) с богатыми тактильными паттернами | **Готово**: реализована команда `haptics.impact`. |

## 3. Куда двигаться: Рекомендуемый пошаговый план развития

### Фаза 1. Завершение сквозного сетевого подключения (Критический этап)
Без этого устройство не зафиксируется в аккаунте.
1. **Реализация Noise XX в Swift**:
   - Использовать `CryptoKit.Curve25519` для генерации эфемерных ключей и согласования секретов (ECDH Curve25519).
   - Использовать `CryptoKit.ChaChaPoly` для шифрования сообщений рукопожатия и последующего потока данных.
   - Использовать HKDF-SHA256 для вывода симметричных ключей `CipherState` (Send/Receive).
2. **WebSocket & Framing транспорт**:
   - Использовать системный `URLSessionWebSocketTask`.
   - Реализовать бинарный фрейминг Muse Noise Envelope (согласно `Vendor/muse-gadget-sdk/linux/src/musegadget/noise/`).
3. **Link RPC Client**:
   - При подключении к VM отправлять запрос `/link-control` со структурой `link.register`.
   - Обрабатывать входящие вызовы `link.invoke` и маршрутизировать их в `IOSCommandRegistry.invoke`.
   - Отправлять ответы `link.result`.
   - Обрабатывать событие `link.unpaired` (очистка Keychain и сброс состояния).
4. **Фоновая работа в iOS**:
   - Так как iOS выгружает приложения из фона, настроить:
     - `UIBackgroundModes`: `audio` (активная аудиосессия предотвращает засыпание при общении);
     - `idleTimerDisabled = true` (режим умной настольной фоторамки/док-станции при подключённой зарядке).

### Фаза 2. Реализация голосового интерфейса (Voice & Audio)
1. **Голосовые заметки / диалог**:
   - Запись входящего звука через `AVAudioEngine` в формате PCM 24 kHz mono (или WAV).
   - Отправка пользовательского голоса через API сессии Muse (`/voice/note` или Link HTTP stream).
2. **Озвучивание ответов Muse**:
   - Приём потокового PCM аудио от сервера Muse и воспроизведение через динамики iPhone с низкой задержкой.
   - Поддержка прерывания речи (barge-in): если пользователь начинает говорить, воспроизведение ответа Muse немедленно глушится.

### Фаза 3. Визуальный интерфейс (Экран как компаньон)
1. **Режим док-станции / умного дисплея (Smart Display)**:
   - Полноэкранный красивый UI, адаптированный под настольное положение (вертикальное и горизонтальное).
   - Показ живого аватара Muse, карточек с погодой, напоминаниями, котировками, умным домом.
   - Отображение текстовых расшифровок ответов нейросети.
2. **Команда `camera.capture`**:
   - Подключение `AVCaptureSession`. При вызове команды от Muse делать качественный кадр, сжимать в JPEG и отправлять обратно в base64 (чтобы Muse «видел» обстановку в комнате).

### Фаза 4. Интеграция с локальной сетью (Skills Hub)
- Старый iPhone постоянно подключен к домашнему Wi-Fi и может выступать шлюзом для локальных устройств, выполняя команды Muse без доступа устройств в интернет (управление Philips Hue, ресиверами, телевизорами, розетками).

---

## 4. Заключение

Главная причина проблемы с аккаунтом ясна и детерминирована: **в проекте завершена только стадия Bluetooth-сопряжения, но отсутствует сетевой клиент регистрации (Noise XX + Link RPC)**. Как только будет реализовано рукопожатие с VM и отправка `link.register`, устройство мгновенно появится в аккаунте Muse.

Аппаратный потенциал iPhone/iPad как гаджета для Muse колоссален: это полноценный Smart Display со встроенной камерой, микрофоном и динамиком, на порядки превосходящий ESP32 по качеству звука, графики и стабильности.
