# Pal Again: полный справочник функций простым языком

Дата проверки: 5 ноября 2026 года.

Этот документ отвечает на четыре вопроса по каждой возможности:

1. Что она делает для обычного пользователя.
2. Есть ли она в Pal Again сейчас.
3. Проверена ли она на настоящем iPhone или iPad.
4. Что конкретно потребуется для её завершения или внедрения.

## Важное правило об аватаре

Запрет относится только к работе агентов с текущим аватаром владельца проекта: его нельзя сбрасывать, удалять, заменять или использовать для экспериментальных проверок без отдельной прямой просьбы владельца.

Это не ограничение продукта. Обычный пользователь вправе установить, заменить или удалить собственный аватар. Команда `display.clear_avatar` и кнопка удаления являются нормальными функциями Pal Again и должны остаться.

## Как читать статусы

- **Работает на устройстве** — есть фактическая проверка на iPhone или iPad.
- **Реализовано, но не проверено** — код и тесты существуют, но полного живого результата ещё нет.
- **Частично** — основа существует, но официальная возможность реализована не полностью.
- **Нет** — функции в приложении пока нет.
- **Не переносим** — функция предназначена для Linux или ESP32 и в таком виде на iOS либо невозможна, либо опасна.

# Часть 1. Основа приложения

## 1. Создание пары

**Что делает:** превращает iPhone или iPad в новый гаджет Muse. Пользователь вводит собственный SDK token, запускает pairing, а затем добавляет найденное устройство в Muse.

**Состояние:** работает на устройстве.

**Что уже есть:** Bluetooth-реклама, pairing v5, криптография, Wi-Fi provisioning, сохранение credential в Keychain.

**Что ещё нужно:** только регрессионные проверки при изменениях SDK. Переписывать эту часть не требуется.

## 2. Защищённое подключение к Muse

**Что делает:** после пары приложение находит VM пользователя, устанавливает зашифрованный Noise XX-канал и регистрирует iPhone/iPad как гаджет.

**Состояние:** работает на устройстве.

**Что уже есть:** VM discovery, Noise XX, `link.register`, token rotation, ping, reconnect.

**Что ещё нужно:** длительный тест стабильности и аккуратная проверка изменений текущего upstream.

## 3. Автоматическое восстановление соединения

**Что делает:** если Wi-Fi кратко пропал или приложение вернулось на экран, Pal Again подключается снова без новой пары.

**Состояние:** работает.

**Ограничение:** после ухода приложения в фон iOS примерно через 30–37 секунд приостанавливает обычное сетевое соединение. Это системное ограничение, а не ошибка Muse.

**Как улучшать:** показывать понятный статус «Приостановлено системой» и автоматически переподключаться при возврате. Нельзя маскировать приложение под фоновое аудио ради обхода App Store.

## 4. Работа с двумя гаджетами

**Что делает:** один пользователь может иметь отдельно зарегистрированные iPhone и iPad.

**Состояние:** работает на устройстве.

**Что ещё нужно:** понятные имена устройств, чтобы Muse и пользователь не путали два одинаковых iPhone или iPad.

# Часть 2. Чат и ответы

## 5. Обычный текстовый чат

**Что делает:** пользователь пишет сообщение и видит потоковый ответ Muse.

**Состояние:** работает на устройстве.

**Что ещё нужно:** кнопка остановки ответа, серверная история и поддержка отдельных разговоров.

## 6. Отправка фотографии

**Что делает:** пользователь выбирает или снимает фотографию, добавляет вопрос и отправляет всё Muse.

**Состояние:** работает на устройстве.

**Что ещё нужно:** проверить большие фотографии, ошибки слабой сети и повторную отправку.

## 7. Голосовая заметка

**Что делает:** пользователь записывает WAV-сообщение, отправляет его, а Muse отвечает как на обычное сообщение.

**Состояние:** работает на устройстве.

**Важно:** это не живой голосовой разговор. Сейчас это эквивалент голосового сообщения в мессенджере.

## 8. Локальная история

**Что делает:** после перезапуска приложения старые сообщения остаются на устройстве.

**Состояние:** работает.

**Ограничение:** это копия Pal Again, а не авторитетная история Muse.

## 9. Синхронизация через iCloud

**Что делает:** переносит текстовую историю между устройствами с одним Apple ID.

**Состояние:** частично проверено.

**Ограничения:** фотографии не переносятся полностью; устройства с разными Apple ID через iCloud не синхронизируются.

## 10. Синхронизация устройств по локальной сети

**Что делает:** два Pal Again с одним token могут обменяться локальной историей без общего Apple ID.

**Состояние:** код существует, на физических iPhone/iPad полностью не подтверждено.

**Как завершить:** включить на двух устройствах, отправить по одному безопасному тестовому сообщению, проверить объединение и отсутствие дублей.

## 11. Серверная история Muse

**Что делает для пользователя:** после переустановки Pal Again загружает настоящий список последних разговоров с сервера Muse. Сообщения, созданные другим клиентом, тоже появляются.

**Состояние:** нет.

**Почему отсутствует:** ранняя версия SDK, по которой начиналось приложение, не давала используемого Pal Again маршрута истории. В актуальном SDK уже документирован `GET /chat/history`.

**Как внедряем:**

1. Добавляем безопасный GET-запрос через существующий Noise transport.
2. Загружаем историю небольшими страницами, чтобы не превысить размер Noise frame.
3. Преобразуем серверные сообщения в `MuseChatItem`.
4. Объединяем их с локальными по ID и времени без дублей.
5. Не удаляем локальную историю при временной ошибке сервера.
6. Добавляем ручную кнопку «Синхронизировать историю».

**Приоритет:** очень высокий.

## 12. Остановка текущего ответа

**Что делает:** как кнопка Stop в ChatGPT — прекращает длинный ответ, если пользователь уже получил нужное.

**Состояние:** нет.

**Почему отсутствует:** основной поток чата был реализован раньше управления жизненным циклом запроса.

**Как внедряем:**

1. Храним идентификатор активного запроса.
2. Показываем Stop вместо кнопки отправки, пока идёт ответ.
3. Отменяем локальный HTTP/Noise stream.
4. Если протокол текущей сессии поддерживает серверную отмену, посылаем её.
5. Сохраняем уже полученную часть ответа с пометкой «Остановлено».

**Приоритет:** очень высокий.

## 13. Отдельные разговоры, или side chats

**Что делает:** позволяет таймеру, виджету, домашнему устройству или отдельной задаче вести собственный разговор, не смешивая всё с главным чатом.

**Состояние:** частично. Pal Again умеет прочитать `session_id` из ответа, но не предоставляет полноценное открытие и продолжение таких разговоров.

**Как внедряем:** добавляем выбор активной сессии, передачу `session_id` при отправке, список недавних сессий и возврат в основной чат.

**Приоритет:** средний.

## 14. Просмотр последнего ответа на весь экран

**Что делает:** превращает старый iPhone в удобный настольный экран: текст ответа крупный, чат и клавиатура не мешают.

**Состояние:** нет как отдельного режима.

**Источник идеи:** свежий ESP32 SDK уже добавил full-screen replies и настройку размера текста на маленьких экранах.

**Как внедряем:** по нажатию на ответ или кнопку в шапке открываем полноэкранное чтение, поддерживаем Dynamic Type, прокрутку и возврат в чат.

**Приоритет:** средний.

## 15. Просмотр предыдущих ответов аппаратным или экранным управлением

**Что делает:** позволяет быстро листать последние ответы, не прокручивая весь чат.

**Состояние:** нет.

**Как внедряем:** отдельный компактный просмотр последних сообщений с кнопками назад/вперёд или жестами.

**Приоритет:** низкий или средний.

# Часть 3. Голос

## 16. Локальное произнесение текста — `audio.speak`

**Что делает:** Muse присылает текст, а iPhone/iPad произносит его системным голосом Apple.

**Состояние:** работает на iPad.

**Ограничение:** это голос iOS, а не поток озвучки, подготовленный Muse.

## 17. Настройка громкости речи — `voice.configure`

**Что делает:** меняет внутреннюю громкость `audio.speak`, не отменяя работу физических кнопок громкости.

**Состояние:** реализовано, но живая проверка изменения громкости не завершена.

**Как проверить:** один короткий текст на 20%, затем тот же на 80%, без длинных сообщений.

## 18. Удалённая запись — `voice.record`

**Что делает:** Muse может попросить гаджет записать короткий фрагмент микрофона и вернуть его как результат команды.

**Состояние:** реализовано, но не проверено полноценным живым вызовом.

**Ограничение:** запись ограничена, требует разрешения и активного приложения.

## 19. Серверная озвучка ответа — `stream_tts`

**Что делает для пользователя:** Muse отвечает голосом, а Pal Again воспроизводит MP3-поток этого конкретного ответа. Это может звучать и вести себя иначе, чем системный голос Apple.

**Состояние после живой проверки 2026-11-05:** серверный путь пока нельзя включать пользователю.

- Если запросить ответ сразу в голосовом режиме, Muse возвращает заглушку «Sorry, I ran into a problem…». Её MP3 действительно доступен: HTTP 200, 37 056 байт, но это озвучка ошибки, а не нормального ответа.
- Если получить нормальный текстовый ответ и затем запросить для него TTS, оба официальных маршрута (`/api/voice/tts-stream` и `/voice/tts-stream`) отклоняют ID сообщения: HTTP 400, тело 120 байт.

Поэтому Pal Again оставляет обычный текстовый режим, а сломанный переключатель озвучки удалён. Системный голос Apple не подменяет голос Muse. Повторная реализация имеет смысл только после того, как сервер начнёт принимать ID успешного текстового ответа либо голосовой режим перестанет возвращать заглушку.

## 20. Живой голосовой разговор — realtime voice

**Что делает для пользователя:** пользователь нажимает кнопку разговора и общается с Muse почти как по телефону: звук идёт потоком, можно видеть субтитры и завершить звонок.

**Состояние:** нет.

**Почему отсутствует:** это отдельный протокол, существенно сложнее голосовой заметки. В официальном SDK он развивался позже и продолжает активно меняться.

**Как внедряем по этапам:**

1. Отдельный экран звонка и явная кнопка начала.
2. `POST /voice/realtime` через отдельную Noise-сессию.
3. Захват PCM с микрофона через AVAudioEngine.
4. Приведение sample rate к требуемому сервером.
5. Воспроизведение входящего PCM.
6. Half-duplex сначала: либо слушаем, либо говорим.
7. Субтитры и индикатор состояния.
8. `POST /voice/end-call` и гарантированное освобождение микрофона.
9. Только после стабильности — full duplex и barge-in.

**Риски:** echo cancellation, Bluetooth audio route, iPhone 6s performance, interruption от телефонного звонка, App Store privacy.

**Приоритет:** высокий, но отдельная крупная фаза.

# Часть 4. Экран, карточки и аватар

## 21. Короткая подпись — `display.set_caption`

**Что делает:** показывает короткий текст состояния, например «Ищу погоду» или «Свет включён».

**Состояние:** реализовано, но не подтверждено отдельным живым вызовом.

## 22. Яркость — `display.set_brightness`

**Что делает:** позволяет Muse изменить яркость экрана в пределах 0–100%, пока приложение открыто.

**Состояние:** реализовано, но не проверено вживую.

**Ограничение:** приложение не должно мешать пользователю вернуть яркость системным способом.

## 23. Закреплённая карточка — `display.show_card`

**Что делает:** показывает над чатом постоянную полезную плитку: текст, таймер или прогресс.

**Состояние:** работает; таймер переживал переустановку/перезапуск и продолжал отсчёт.

**Как развивать:** добавить действия на карточке, несколько типов, срок действия и accessibility.

## 24. Очистка карточки — `display.clear_card`

**Что делает:** убирает закреплённую карточку после выполнения задачи.

**Состояние:** реализовано, но отдельно не проверено.

## 25. Показ картинки из VM — `display.draw_file`

**Что делает:** Muse сохраняет изображение в своей VM, а Pal Again безопасно получает и показывает его над чатом.

**Состояние:** работает на iPad.

**Почему это лучше прямого URL:** серверная VM становится контролируемым посредником; приложение не превращается в средство запроса произвольных интернет-адресов.

## 26. Очистка картинки — `display.clear_image`

**Что делает:** закрывает картинку, показанную командой `display.draw_file`.

**Состояние:** реализовано, но отдельно не проверено.

## 27. Аватар и его состояния

**Что делает:** показывает лицо/персонажа Muse и переключает idle, listening, thinking и speaking.

**Состояние:** работает на iPad и iPhone 6s.

**Особенность:** Pal Again получает файлы из VM и хранит их локально. Это собственное расширение Pal Again; официальный ESP32 обычно рисует локальный аватар из прошивки.

**Что делать дальше:** улучшать плавность и восстановление состояния. Пользовательские установка, замена и удаление остаются доступны; агентам нельзя проверять их на текущем аватаре владельца проекта.

## 28. Одноразовая анимация — `display.play_avatar`

**Что делает:** проигрывает короткую реакцию, например радость, а затем возвращает обычное состояние.

**Состояние:** код есть; автоматические изменения состояния видны, но прямой вызов конкретной одноразовой реакции отдельно не подтверждён.

## 29. Имя возле аватара — `display.set_name`

**Что делает:** сохраняет имя персонажа рядом с аватаром.

**Состояние:** реализовано, но живая проверка сохранения после перезапуска не завершена.

## 30. Удаление аватара — `display.clear_avatar`

**Что делает:** удаляет пользовательский аватар и возвращает стандартную картинку.

**Состояние:** сейчас команда и кнопка существуют.

**Решение проекта:** оставить функцию. Пользователь самостоятельно распоряжается собственным аватаром.

**Правило проверки:** не тестировать удаление на текущем аватаре владельца проекта. Для автоматических и физических тестов использовать отдельный тестовый профиль, временный тестовый аватар или mock-хранилище.

# Часть 5. Возможности самого iPhone/iPad

## 31. Состояние устройства — `device.health`

**Что делает сейчас:** сообщает Muse тип системы, версию iOS, общий тип устройства и заряд.

**Состояние:** реализовано, но слишком бедно и отдельно не проверено живым вызовом.

**Как расширяем безопасно:**

- заряд и подключение питания;
- thermal state;
- Low Power Mode;
- свободное место;
- яркость;
- версия и build Pal Again;
- время соединения;
- последний успешный ping;
- состояние foreground/background;
- статусы разрешений;
- наличие фонарика, камеры, микрофона и motion.

**Что нельзя обещать:** полную диагностику диска, файловой системы и процессов как на Linux. iOS не предоставляет приложению такой доступ.

## 32. Вибрация — `haptics.impact`

**Что делает:** физически привлекает внимание пользователя.

**Состояние:** работает на iPhone 6s через системную вибрацию. На iPad соответствующего оборудования нет.

## 33. Фонарик — `torch.set`

**Что делает:** включает и выключает вспышку камеры.

**Состояние:** работает на iPhone 6s; правильно возвращает ошибку на iPad без вспышки.

## 34. Камера — `camera.capture`

**Что делает:** по команде снимает один уменьшенный JPEG и возвращает его Muse.

**Состояние:** реализовано, но полный живой E2E ещё не подтверждён.

**Безопасность:** только при разрешённой камере, активном приложении и с ограничением размера.

## 35. Геопозиция — `location.current`

**Что делает:** возвращает приблизительное текущее местоположение для погоды, маршрута или локальных действий.

**Состояние:** реализовано, но живой вызов не подтверждён.

**Безопасность:** пользователь выдаёт системное разрешение; приложение не должно включать постоянное фоновое слежение.

## 36. Движение — `motion.snapshot`

**Что делает:** сообщает, лежит ли устройство спокойно, повернули ли его, подняли или встряхнули.

**Состояние:** работает на iPad; реальные acceleration, rotation, attitude и gravity уже появились в чате.

**Как развивать:** добавить понятные высокоуровневые события «подняли», «повернули», «встряхнули», не заставляя Muse самостоятельно интерпретировать сырые числа.

## 37. Дополнительные датчики iPhone

**Что может быть полезно:** компас, барометр на поддерживаемых устройствах, proximity на iPhone, orientation, ambient-like state через яркость/режим экрана.

**Состояние:** нет отдельного общего `sensors.read`.

**Как внедряем:** рекламируем только реально доступные конкретному устройству датчики и возвращаем единицы измерения, точность и возраст показания.

**Приоритет:** средний или низкий.

# Часть 6. Shortcuts и локальные устройства

## 38. Запуск Apple Shortcut — `shortcuts.run`

**Что делает:** через заранее одобренную команду может включать HomeKit-сцены, создавать напоминания, отправлять данные другому приложению и выполнять личные автоматизации.

**Состояние:** простой Shortcut с уведомлением запускался на iPhone 6s.

**Что ещё нужно:** подтвердить получение текстового результата и сценарии завершения дольше 25 секунд.

## 39. Список разрешённых Shortcuts — `shortcuts.list`

**Что делает:** показывает Muse только те имена Shortcuts, которые пользователь уже разрешил в Pal Again.

**Состояние:** реализовано, живой E2E не подтверждён.

**Ограничение iOS:** приложение не может свободно прочитать полный список чужих Shortcuts.

## 40. Поиск устройств — `lan.discover`

**Что делает сейчас:** находит некоторые сервисы Bonjour в локальной сети.

**Состояние:** реализовано, но на реальной домашней сети полностью не проверено.

**Отличие от ESP32:** официальный `device.discover` также использует ARP, SSDP, SNMP и NetBIOS. Pal Again пока не имеет такого охвата.

## 41. Локальный HTTP(S)-запрос — `lan.request`

**Что делает:** после одобрения пользователя обращается к конкретному домашнему устройству, например Home Assistant или локальному API.

**Состояние:** реализовано, но живой запрос к настоящему устройству ещё не подтверждён.

**Защита:** частные IP/`.local`, одобренный host:port, запрет redirect, ограничение ответа, TLS TOFU.

## 42. SSDP/UPnP

**Что даст:** поиск телевизоров, медиаплееров, Sonos и другой бытовой техники.

**Состояние:** нет.

**Как внедряем:** отдельный UDP discovery-модуль с пользовательским запуском, ограничением времени и понятным списком найденного.

## 43. WebSocket

**Что даст:** постоянные локальные обновления от Home Assistant и других контроллеров.

**Состояние:** нет для локальных устройств; Muse transport WebSocket уже существует отдельно.

**Как внедряем:** разрешение каждого endpoint, TLS pinning, лимит сообщений и остановка при уходе приложения в фон.

## 44. MQTT

**Что даст:** датчики, Zigbee2MQTT, Home Assistant и множество DIY-устройств.

**Состояние:** нет.

**Как внедряем:** только явные broker profiles, Keychain для пароля, topic allowlist и запрет произвольной подписки без подтверждения.

## 45. Chromecast, Sonos, Hue, Home Assistant и другие адаптеры

**Что дают:** понятные команды вроде «поставь музыку», «включи свет», «покажи состояние дома».

**Состояние:** частично достижимо через Shortcuts или HTTP, но готовых нативных адаптеров нет.

**Как внедряем:** поверх общих безопасных транспортов делаем отдельные адаптеры с человеческими командами. Не переносим Linux shell-команды дословно.

## 46. BLE central

**Что даст:** iPhone сможет находить и обслуживать внешние Bluetooth LE-датчики и устройства.

**Состояние:** нет; текущий Bluetooth используется главным образом для pairing, где Pal Again выступает гаджетом.

**Как внедряем:** CoreBluetooth scan/connect/discover/read/write/subscribe, отдельное разрешение каждого устройства и UUID вместо MAC-адресов.

**Ограничения:** iOS не позволяет приложению программно включить Bluetooth и ограничивает background.

# Часть 7. Файлы и содержимое VM

## 47. Чтение файла из VM

**Что делает сейчас:** специальный сервис читает изображения и аватарные файлы через `/fs/raw`.

**Состояние:** работает для предназначенных медиа.

## 48. Общий безопасный обмен документами

**Что даст:** Muse сможет положить пользователю отчёт, текст, картинку или другой разрешённый документ, а Pal Again — показать или сохранить его.

**Состояние:** общего API нет.

**Как внедряем:**

1. Создаём отдельный каталог Pal Again Documents.
2. Не разрешаем выход за его пределы.
3. Ограничиваем тип и размер файлов.
4. Добавляем preview до сохранения.
5. Запись или экспорт выполняем только после действия пользователя.

## 49. Linux `file.read`, `file.write` и `system.run`

**Что делают на Linux:** читают и записывают файлы машины, запускают shell-команды, обеспечивают Disk Doctor и системное администрирование.

**Решение для iOS:** не переносить буквально. iOS sandbox не даёт такого доступа, а универсальная удалённая команда была бы опасна и неприемлема для App Store.

**Правильная замена:** расширенный `device.health`, безопасная папка документов, Shortcuts и отдельные локальные адаптеры.

# Часть 8. Возможности ESP32, неприменимые напрямую

## 50. OTA-прошивка — `device.ota`

**Что делает:** обновляет прошивку ESP32.

**Решение:** никогда не регистрировать в Pal Again. Обновления iOS-приложения выполняет App Store.

## 51. Локальные датчики температуры, CO2 и влажности

**Что делает:** ESP32 читает физически подключённые сенсоры.

**Решение:** не обещать на iPhone, если такого сенсора нет. Можно получать данные внешнего BLE/HomeKit/MQTT-датчика через отдельный адаптер.

## 52. Локальная отрисовка ESP32-аватара

**Что делает:** прошивка рисует пиксельного персонажа из локальных ассетов.

**Решение:** не переносить исходный C-рендерер. Существующая система MP4/VM в Pal Again уже лучше соответствует iOS.

## 53. `display.draw_url`

**Что делает:** ESP32 сам загружает картинку по URL.

**Решение:** не добавлять без отдельной необходимости. Текущий путь «Muse сохраняет файл в VM → Pal показывает файл» безопаснее.

# Часть 9. Официальные мобильные видеопримеры

## 54. Камера телефона на экране ESP32

**Что делает:** официальный iOS/Android test app передаёт H.264 или VP8-видео с камеры телефона на совместимую ESP32-плату в локальной сети.

**Состояние в Pal Again:** нет.

**Важно:** это не чат и не gadget runtime. Это отдельный прямой видеоканал «телефон → ESP32».

**Как внедряем:** как отдельный дополнительный экран только после основной версии 2; пользователь вручную выбирает получателя и запускает трансляцию.

# Часть 10. Почему функции не появились раньше

Подтверждённые причины:

- Pal Again начинался с pinned SDK `4a857e3`; текущий upstream уже ушёл вперёд на 44 коммита.
- Realtime voice является отдельным сложным протоколом, а не небольшим дополнением к голосовым заметкам.
- Официальные iOS/Android каталоги SDK не являются полноценным gadget runtime, поэтому готовую реализацию для Pal Again оттуда взять нельзя.
- Linux shell и произвольная файловая система несовместимы с моделью безопасности iOS.
- Некоторые ESP32-команды зависят от физического оборудования конкретной платы.
- Background runtime ограничивается самой iOS.

Вероятные, но не подтверждённые историческими решениями причины:

- сначала доводились pairing, Noise, чат и App Store-ready интерфейс;
- часть свежих SDK-функций появилась уже после начала разработки;
- функции могли быть отложены до появления работающего базового канала и реальных устройств.

Нельзя утверждать без истории коммитов или слов автора, что конкретная функция была «забыта». Для каждого пункта выше отдельно указано: она невозможна, намеренно неприменима, появилась позже либо просто ещё не реализована.

# Часть 11. Как следить за официальным SDK дальше

Чтобы не повторять аудит вручную каждый час:

1. Оставить submodule закреплённым на проверенной версии.
2. Добавить документ `Docs/UPSTREAM-TRACKING.md` с текущим локальным и последним рассмотренным upstream commit.
3. Раз в неделю или перед версией запускать скрипт, который показывает новые upstream commits по каталогам `linux`, `esp32`, `protocols`, `ios` и `android`.
4. Для каждого нового upstream commit записывать решение:
   - перенести;
   - уже реализовано иначе;
   - неприменимо к iOS;
   - отложить;
   - требует исследования.
5. Обновлять submodule только после ревью и теста двух физических устройств.
6. Не использовать обновление submodule как автоматическое изменение production-кода Pal Again.

# Часть 12. Полная проверка перед признанием функции рабочей

Для каждой команды нужны четыре уровня:

1. Unit test параметров, ошибок и результата.
2. Protocol test: команда зарегистрирована и возвращает корректный `link.result`.
3. Физический тест на iPad.
4. Физический тест на iPhone 6s, если функция там применима.

Отдельно фиксируются:

- разрешение выдано или запрещено;
- приложение на экране или в фоне;
- аппаратная возможность существует или отсутствует;
- пользователь реально увидел/услышал/почувствовал результат;
- аватар владельца проекта не изменялся и не сбрасывался без его отдельной прямой просьбы.
